## Насущные вопросы/проблемы/действия

### Формат хранения свёрток
- [x] **Изменить способ получения количества данных**

    При превращении свёрток в массив байтов перед свёрткой добавляются 4 байта, в которых хранится количество элементов свёртки. Это необходимо для адекватной работы PackedArray. 

    >**Вопрос:** стоит ли переделать программу так, чтобы количество элементов высчитывалось самостоятельно по количеству элементов по горизонтали и вертикали (эти данные есть в БД), а в самом массиве байтов хранить только саму свёртку?

    >**Ответ:** да, надо сделать так, чтобы в BYTEA лежала только сама свёртка. Всё остальное должно лежать рядом.

    >**Действие:** изменить способ получения количества данных.

    >**Материалы:** скинутое задание из YouTrack

### SQL-запросы к базе данных
- [ ] **Создать SQL-запросы**

    Необходимо создать SQL-запросы, которые позволят увидеть свёртки без графического интерфейса, просто с доступом к базе данных. Должна отображаться некая гистограмма.

    >**Материалы:** скинутый вайбкод

### Интерполяция
- [ ] **Создать интерполятор и сравнивать значения**

    Необходимо создать интерполятор, превращающий малобитные свёртки в нечто адекватно выглядящее. Понять, при каком количестве бит на значение выбросы интерполяции становятся вредными настолько, что дальше лучше не сжимать.

    >**Материалы:** скинутое задание из YouTrack

### Кеширование сжатых свёрток для спарклайна
- [ ] **Перенести расчёт сжатых свёрток дальше от модели таблицы**

    Сжатые свёртки для отрисовки спарклайна можно расчитывать непосредственно при получении несжатой. Это позволит не заниматься записью огромных свёрток, а также позволит избавиться от первичного залагивания интерфейса при отображении таблицы.
