# 3D-просмотрщик свёрток

Отдельная локальная микропрограмма для PostgreSQL. Она не импортирует классы
`myConvolution`, не запускает Qt-приложение и не входит в его сборку.

## Быстрый запуск на macOS

Дважды щёлкните `tools/run_convolution_3d_viewer.command`.

При первом запуске рядом с просмотрщиком создаётся изолированная `.venv` и
ставятся три зависимости. Затем автоматически открывается браузер. В форме
подключения уже подставлены пользователь `russkiylis` и пароль `1337`; пароль
используется только локальным просмотрщиком. Изменения полей формы не
сохраняются.

В интерфейсе также есть кнопка **Демо без БД**.

## Запуск из терминала

```bash
./tools/run_convolution_3d_viewer.command
```

Демо сразу после открытия:

```bash
tools/convolution_3d_viewer/.venv/bin/python \
  tools/convolution_3d_viewer/app.py --demo
```

Можно заранее задать стандартные переменные PostgreSQL: `PGHOST`, `PGPORT`,
`PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGSSLMODE`. Значения `PGUSER` и
`PGPASSWORD` переопределяют встроенные значения по умолчанию; пароль из
`PGPASSWORD` в браузер не передаётся.

## Что показывает программа

- всю историю сохранённых записей для каждой пары «имя поста + `data_type`»;
- вращаемую/масштабируемую Plotly 3D-поверхность;
- верхние фильтры по посту и всем доступным типам;
- таблицу отдельных сохранений выбранной пары: время, ID, результат H/V,
  качество и сетку; любая строка открывает именно эту свёртку;
- сравнение двух типов с синхронным вращением камеры;
- реальный максимум, координаты пика, качество, сетку и метаданные результата;
- сохранение изображения через стандартную панель Plotly.

Горизонтальная и вертикальная оси имеют единый угловой масштаб: один градус H
и один градус V занимают одинаковую длину. Поэтому форма пика не искажается
произвольным соотношением сторон сцены.

Большие сетки прореживаются max-pooling по блокам: пик не теряется, а браузер
остаётся отзывчивым. Сначала загружается только лёгкий каталог истории без
`BYTEA`; массив выбранной записи читается отдельным запросом по её ID. Поэтому
просмотрщик не держит в памяти все сохранённые свёртки сразу. Исходный `BYTEA`
и база не изменяются.

## SQL-контракт

По умолчанию выполняется `query.sql` из этой папки. Это каталог всех записей с
метаданными, но без тяжёлого поля `conv`. Просмотрщик разрешает ровно одну
SQL-команду и исполняет её в зафиксированной read-only транзакции. Если запрос
заменяется, это должен быть один `SELECT`, возвращающий те же обязательные
алиасы и уникальный `id` каждой записи.

После выбора строки просмотрщик выполняет собственный фиксированный
параметризованный `SELECT` по этому `id` и получает `conv`. Поддерживается
`BYTEA` формата `double/real/smallint/pa_2b..pa_8b` с суффиксом `_le` или
`_be`. Запись можно открыть только если её ID присутствовал в последнем
загруженном каталоге.

Web-сервер слушает только loopback и защищает запросы случайным токеном. Для
остановки нажмите `Ctrl+C` в терминале.
